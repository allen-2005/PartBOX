# PartBOX 项目表格精修设计

## 目标

让“我的项目”表格与元件库存保持一致、可排序且不串选中状态，并补齐项目用量、价格统计、批量删除和项目右键管理。

## 已确认交互

- 项目中的“商品类型”直接读取元件库存的 `product_type`，不再次简化分类。
- 项目表格使用与库存表相同的上下双三角排序提示；序号列永远显示当前可见位置的 1、2、3，不跟着元件身份移动。
- 库存和项目的勾选状态都绑定数据库 component ID；排序、刷新后仍选中原元件。复选框描边改为 1 像素。
- 新导入项目的元件用量为 1；项目用量使用带上下箭头的整数控件，最小值为 1。
- 项目表最右侧加入单价、小计。单价来自库存 `latest_unit_price`，小计为单价乘用量；项目总额在表格上方实时显示。
- 项目列表右键提供新建、重命名、删除操作，原顶部按钮继续保留。
- 项目表支持批量勾选并删除。删除时忽略尚未同步的用量编辑；只把该行 `synced_quantity` 对应的已扣库存全部退回，写入 `project_return` 库存流水和项目操作记录，然后删除项目行。
- 项目页的列顺序为：序号、商品编号、商品类型、商品名称、商品型号、封装格式、品牌、项目用量、单价、小计。勾选框位于独立的最左侧行头。

## 数据和原子性

`ProjectService.remove_components(project_id, component_ids)` 在一个 SQLite 事务内完成库存回补、库存流水、项目操作明细和项目行删除。任一步失败全部回滚。若所选行都从未同步，直接删除且不创建空操作记录。

数据库初始化时把旧版本中小于 1 的项目用量迁移为 1；`synced_quantity` 保持原值，以便下次同步只扣新增差额。

## UI 结构

库存表和项目表共用轻量的行选择表头绘制逻辑，但各页面独立保存 ID 集合。项目横向表头复用库存表的三角绘制风格，项目页不新增列隐藏持久化需求。

项目用量由 `QSpinBox` 委托持续显示，上下箭头可直接点击。值改变后立即写数据库并刷新小计与项目总额；失败时恢复数据库值并提示。

## 验收

- 主库存选中若干行后切换排序，选中的 product code 不变。
- 项目表排序后，选中元件不变，序号仍从 1 连续排列。
- 新加入项目的行用量为 1，不能调到 0。
- 修改用量时小计和总额同步更新，价格排序按数值而非字符串。
- 删除已同步项目行后库存准确回补，并存在 `project_return` 流水；未同步编辑不影响回补数量。
- 项目类型文本与对应库存记录完全相同。
