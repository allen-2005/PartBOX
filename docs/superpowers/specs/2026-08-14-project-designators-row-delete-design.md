# PartBOX 项目位号与逐行删除设计

## 目标

在“我的项目”元件表最右侧新增“位号”和“操作”两列。位号属于项目 BOM 配置；删除按钮直接作用于所在行，不依赖左侧勾选。

## 表格布局

- “位号”位于“小计”右侧，默认宽度约 150 px。
- “操作”位于最右侧，固定为窄列，表头显示“操作”。
- 每行操作单元格显示一个简约线框垃圾桶按钮，悬停提示“删除该元件”。
- 操作列不参与编辑；位号列是项目表中唯一可直接输入文本的普通单元格。

## 位号编辑与保存

- 位号允许空值和任意常用 BOM 文本，例如 `R1`、`R1,R2`、`C3-C6`。
- 单击位号单元格即可进入编辑。
- 编辑时按 `↑` 或 `↓`：先提交当前输入，再移动到同一列的上一行或下一行并继续编辑；到达首行或末行时停留在边界行。
- 位号和项目用量共用草稿状态。任一位号或用量变化都会启用“保存元件配置”。
- “保存元件配置”在同一数据库事务中保存完整的项目用量与位号映射；不修改库存、不修改已同步数量、不写库存流水或项目操作记录。
- 切换项目、关闭软件、从库存页向项目导入元件时，沿用现有保存／放弃／取消保护，并同时覆盖位号草稿。

## 逐行删除

- 点击某行垃圾桶后弹出确认框，内容包含商品编号或名称，避免删错行。
- 取消不执行任何变化。
- 确认后删除该项目元件。若该元件曾导出到库存，继续沿用现有服务逻辑返还已同步数量并记录返还操作。
- 删除当前行时，其他行尚未保存的用量和位号草稿必须继续保留；被删除行的草稿一并移除。
- 删除完成后刷新项目计数、合计和操作记录。

## 数据与迁移

- 为 `project_components` 增加非空文本列 `reference_designator`，默认空字符串。
- 数据库初始化采用幂等迁移；已有数据库自动增加该列，原项目数据保持不变。
- `ProjectService.list_components()` 返回位号。
- `ProjectService.save_configuration()` 接收每个元件的完整配置（用量与位号），校验元件集合完全一致后原子保存。

## 验证

- 数据库迁移测试：旧数据库升级后拥有位号列且原数据不丢失。
- 服务测试：用量与位号同时保存；库存、同步数量和流水不变；映射不完整时整体回滚。
- UI 测试：位号单击可编辑；上下键提交并移动；草稿启用保存；切换保护包含位号。
- 删除测试：取消不删除；确认只删除所在行；不依赖勾选；其他行草稿保留；已同步元件正确返还库存。
