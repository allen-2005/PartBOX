# PartBOX 仅物料明细原文导入设计

## 目标

PartBOX 只接受立创商城“物料明细对账单”Excel，不再提供或处理“订单详情”Excel。库存表和项目表中的商品编号、商品类型、商品名称、商品型号、封装格式、品牌及商品单位必须来自物料明细单元格原文，不进行大类归并或内容改写。

## 数据流

`parse_statement()` 是唯一的订单导入解析器。商品编号仍去除首尾空白并统一为大写，以保证同一立创编号稳定匹配；品牌、商品类型、商品名称、商品型号、封装格式和商品单位使用保留单元格文本的转换函数。空单元格写为空字符串，Excel 数值型文本按其可见整数形式转换。

`ImportService.commit()` 在命中已有元件时，除累计数量、价格和库存外，也用当前物料明细行更新上述描述字段。这样曾由旧版订单详情导入造成的“电阻／其他”等粗分类，会在用户重新导入物料明细时被原文纠正。筛选按钮仍可根据原文计算“电阻”等快捷大类，但计算结果不得写入数据库或表格字段。

## 界面与兼容

主窗口删除“＋ 导入订单详情”按钮，只保留“＋ 导入物料明细”。订单详情解析函数、专用脚本入口、测试和使用说明一并移除。已有数据库、库存流水、项目和用户备注不删除；修正描述字段不会改变现有库存数量。

## 验证

- 单元测试证明物料明细中的描述字段逐项保持原文。
- 服务测试证明已有元件会被物料明细原文修正，同时库存决策仍生效。
- UI 测试证明订单详情入口不存在。
- 对桌面 6 份真实物料明细逐行比对解析结果和 Excel 源单元格。
- 运行完整测试、构建 EXE，并执行打包后冒烟测试。
